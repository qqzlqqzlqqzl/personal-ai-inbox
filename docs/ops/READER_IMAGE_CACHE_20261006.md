# Reader 图片缓存与动态预热

列表保留选中的原始 cover_url，但浏览器封面仅使用当前条目绑定的 /mf/proxy 签名地址。失败显示占位，不自动直连源站。正文图片处理不变。

服务端 ROOT/state/reader-image-cache 仅保存有效 JPEG/PNG/WebP 图片，文件内容总上限 1GiB、8192个文件、单图8MiB；过期清理及 LRU 淘汰包含临时写入容量。目录0700、文件0600，每次命中仍校验当前签名，错误、损坏图片与 private/no-store/no-cache 响应不缓存。磁盘故障继续既有代理回源。

Miniflux 公共图片响应附带的匿名会话 Cookie 不转发：仅原生200且明确 public 并无禁止缓存策略时保留公共缓存，其余 Cookie 响应仍不缓存。原生代理可见策略是依据，不声称知道其未转发的源站策略。签名地址与宽度组成缓存维度，预热和浏览器统一上游 Accept，避免同图重复缓存。原始 AVIF/GIF 可代理展示，当前不计入磁盘缓存命中。

warm_reader_covers.py --once 在已有运行环境执行。唯一队列是全部 AI精选、score>=8、发布时间从新到旧最多240条，排除已隐藏源与明确不合格正文；不单列今天、不会预热6分内容。通过当前账号的原生轻量元数据核实文章所有权及图片绑定，源图去重，再温热480/960变体。先检查已有缓存，一轮最多30次未命中请求、约110秒；限额、超时和失败在后续轮次继续。小型状态文件仅存哈希和重试时间，失败指数退避，后续未尝试图片优先，避免慢源阻断整个队列。不会写 analyses 或 Miniflux 业务数据库。

ai-news-reader-covers.timer 开机3分钟后及每10分钟自动运行，低优先级使用当前 venv 和私有环境文件。动态更新、淘汰及重试由程序完成，不需用户手动点击；无需为了填满1GiB下载无用图片。

网页首屏先展示，再经两个绘制帧开始前两页后台加载，后续页面让出空闲时段。额外十页逐页串行，并非首开一次等待十页；封面背景队列两路持续加载，切换范围取消旧队列。可见图片仍由浏览器正常加载。

定向验证覆盖签名、公共 Cookie、缓存容量/淘汰、统一 Accept、只读预热、逐页调度和图片组件。生产部署使用同一成功CI生成的前端包与对应源码；定时任务及真实磁盘命中需要部署后确认。
